# Проверка сервиса

Проверено на Python 3.14.3. Команда `python3 -m unittest discover -v` завершилась с результатом **11 тестов, OK**. [Вывод тестов](demo/tests.txt). Команда `python3 demo_run.py` прошла через HTTP-обработчик и вывела ответы ниже. [Запись демонстрации](demo/demo.gif) · [Текстовый вывод](demo/session.txt).

| Сценарий | Фактический результат |
|---|---|
| Корректный запрос | HTTP 200, ответ очищен от внешних пробелов, cached=false. |
| Повтор того же запроса | HTTP 200, cached=true, один вызов клиента на два запроса. В журнале cache_miss, затем cache_hit. |
| Нет message, пустая строка, неверный тип, длина 1001 | HTTP 400, провайдер не вызван. Строка длиной 1000 прошла валидацию. |
| Ошибка соединения | Три попытки, паузы 0,25 и 0,5 с, HTTP 503. После восстановления тот же текст обработан без попадания в кеш. |
| Таймаут | Эмуляция дала HTTP 503 после трёх попыток. Отдельный транспортный тест подтвердил таймаут чтения при задержке ответа сокета. |
| Временный HTTP 503, затем успех | Две попытки, клиент получил HTTP 200. |
| Ошибка авторизации HTTP 401 | Одна попытка, клиент получил fallback с HTTP 503. |
| Сломанный JSON, отсутствующие поля ответа, пустой текст модели | Каждый вариант дал HTTP 503 без повторного обращения. |
| TTL и состав ключа | Запись доступна на 599-й секунде и истекает на 600-й. Изменение текста, модели, температуры или системной инструкции изменяет ключ. |
| Запрос к HTTP-провайдеру | Реальный HTTP-клиент прочитал ответ локального тестового двойника через пару сокетов. |

**Границы автоматического прогона.** Среда выполнения запрещала привязку к TCP-порту. Тесты использовали HTTP по соединённым локальным сокетам и тестовый транспорт для отказов. Проверка через curl на порту 8000 и обращение к реальной модели с ключом в этот прогон не входили.

## Ручной прогон на Mac · 25 ноября 2026

Запросы отправлены через curl на порт 8000. В журнале сервиса подтверждены cache_miss и cache_hit для двух успешных запросов, два ответа 400 на ошибки ввода и три попытки при каждом временном отказе. При таймауте curl зафиксировал 24,774372 с и HTTP 503. После невалидного JSON сервис вернул 503, а следующий запрос без перезапуска получил 200. После остановки провайдера журнал зафиксировал три ConnectionRefusedError, событие fallback и HTTP 503.

## Чек-лист ручной проверки

Запустить локальный тестовый провайдер и сервис по README. В примере curl из README менять только тело запроса.

- [x] Отправить текст из примера. Ожидать 200, резюме и cached=false.
- [x] Повторить его сразу. Ожидать cached=true. В service.jsonl найти cache_miss и cache_hit для двух запросов.
- [x] Отправить пустой объект, затем сообщение из 1001 символа. Оба раза ожидать 400. Для длинного текста можно передать curl аргумент `-d "$(python3 -c 'import json; print(json.dumps(dict(message="a"*1001)))')"`.
- [x] Передать сообщение «сбой». Ожидать три попытки и 503. Остановить тестовый провайдер и отправить новый текст для проверки отказа соединения.
- [x] Снова запустить провайдер, передать «таймаут». Ожидать 503 примерно через 25 секунд (три таймаута по 8 секунд и 0,75 секунды пауз).
- [x] Передать «невалидный JSON». Ожидать однократный вызов и 503. Затем отправить новый обычный текст и получить 200.
- [ ] Для проверки с реальной моделью запустить сервис с личным ключом по README и получить резюме нового текста. Сверить факты в резюме с исходным сообщением.
