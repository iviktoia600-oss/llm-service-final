# Сервис суммаризации текста

`POST /chat` принимает текст и возвращает его краткое резюме на русском языке. Сервис написан на Python 3.9+ и использует стандартную библиотеку. Есть два режима проверки: реальный OpenAI-совместимый API и локальный HTTP-провайдер с фиксированными ответами.

## Запуск на Mac или Linux

Из каталога проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Впишите ключ в `.env` после `OPENAI_API_KEY=`. Выберите доступную вашему аккаунту модель в `LLM_MODEL`. По умолчанию используется `gpt-4o-mini` и эндпоинт Chat Completions. Значения в файле вводятся без кавычек. Переменные окружения имеют приоритет. Файл с ключом исключён из Git.

```bash
python main.py
```

Сервис слушает `127.0.0.1:8000`. Порт можно изменить командой `PORT=8010 python main.py`. Остановить сервер можно сочетанием Ctrl+C. [Формат API провайдера](https://platform.openai.com/docs/api-reference/chat/create).

## Проверка без ключа

В первом терминале из проекта запустите `python3 -m tests.provider`. Во втором выполните:

```bash
OPENAI_API_KEY=demo LLM_URL=http://127.0.0.1:8091/v1/chat/completions python3 main.py
```

Это запускает тот же pipeline, что и при работе с реальной моделью. Тестовый провайдер возвращает заранее заданный текст. Для специальных сообщений `сбой`, `таймаут` и `невалидный JSON` он воспроизводит соответствующую ошибку. Не передавайте реальный ключ локальному провайдеру.

## Примеры

```bash
curl -i http://127.0.0.1:8000/chat -H 'Content-Type: application/json' \
  -d '{"message":"Команда добавила кеш. Затем команда проверила сервис."}'
```

При первом запросе к тестовому провайдеру приходит HTTP 200:

```json
{"answer":"Команда добавила кеш и проверила сервис.","cached":false}
```

Повторите команду в течение 10 минут. Значение `cached` станет `true`. Ответ реальной модели может отличаться. Для проверки валидации отправьте:

```bash
curl -i http://127.0.0.1:8000/chat -H 'Content-Type: application/json' -d '{}'
```

HTTP 400: `{"error":"Поле message должно быть непустой строкой."}`

При недоступности провайдера HTTP 503: `{"error":"Сервис временно недоступен, попробуйте позже."}`. Заголовок `X-Request-ID` связывает ответ с событиями в журнале.

## Как устроен запрос

| Слой | Что делает |
|---|---|
| main.py, api/routes.py | Принимают HTTP POST. Проверяют JSON, тип и длину message (1–1000 символов, строка из пробелов недопустима). |
| services/summary.py | Выполняет сценарий суммаризации, координирует кеш, клиент и обработку ответа. |
| llm/prompt.py | Разделяет системную инструкцию и пользовательский текст, добавляет модель и температуру. |
| cache/results.py | Строит SHA-256 по адресу провайдера и полному запросу, включая оба сообщения, модель и температуру. Хранит до 512 успешных ответов в памяти процесса, TTL 600 секунд. |
| llm/client.py | Выполняет запрос с таймаутом сокета 8 секунд. Для временных ошибок делает до трёх попыток с паузами 0,25 и 0,5 секунды. Извлекает непустой текст и удаляет внешние пробелы. |
| config/events.py | Пишет JSON Lines в консоль и service.jsonl. Для этапа сохраняет начало, длительность и исход, для кеша — hit/miss. |

Ошибки авторизации и разбора ответа приводят к fallback без повторной попытки. После ошибки можно повторить тот же запрос. Успешные ответы кешируются после постобработки. При перезапуске кеш очищается. По условиям задания журнал содержит тексты запросов и ответов, поэтому для демонстрации используются учебные данные.
